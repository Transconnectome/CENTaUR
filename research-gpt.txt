가능합니다. **다만 “무엇을 어떻게 포함하느냐”가 핵심**입니다. CBCL·WISC·KSADS·DSM 관련 자료는 대부분 **저작권·시험보안·데이터 사용계약(DUA/DUC)** 의 제약을 받습니다. 아래 원칙과 구현 계획을 따르면 **한국형·발달 임상 메타데이터**를 **법적·윤리적으로 안전하게** CENTaUR 파이프라인에 통합할 수 있습니다.

## 2) 전략: “과제 전사(centaur 스타일)”는 오픈 과제에, **임상 도구는 ‘메타데이터’로만**

CENTaUR는 **자연어 전사 + 선택 토큰(`<< >>`)만 손실** 구조가 핵심입니다. 따라서 **CBCL/WISC/KSADS/DSM의 문항을 전사로 학습시키지 말고**, 해당 도구에서 나온 **요약 점수·진단·코호트 분류값**을 **입력 맨 앞의 메타 블록**으로만 사용합니다. 이렇게 하면

1. **시험보안/저작권 위반 위험 최소화**,
2. **발달·임상 이질성(연령/진단/증상수준)**을 모델이 “조건부 맥락”으로 활용하여 **의사결정 일반화**를 돕습니다.

> ABCD는 **NBDC Data Hub**로 이전(6.0 릴리스)되어 **새 DUC 체계**를 사용합니다. **승인된 목적 내 연구 사용 + 개인수준 데이터/파생의 외부 공유 금지**를 준수해야 합니다. ([ABCD Study][5])

## 3) 구현 아키텍처(추가)

```

  collators/
    choice_masking.py          # << >> 만 labels, 메타 블록은 -100 (손실 제외)
  datasets/

  training/

      lora_private/            # DUC 제한 메타데이터 상조건 LoRA(공개 금지)
```

## 5) 코드 레벨 — 안전 인코딩 & 마스킹

**(a) 메타 블록 생성기**

```python
# src/centaur_ko/metadata/encoders.py
def meta_to_header(meta: dict) -> str:
    # 숫자는 반올림/클리핑으로 과도한 정밀도 방지(규준 역추정 방지)
    def num(x): 
        return None if x is None else int(round(float(x)))
    fields = [
        f"age_m={num(meta.get('age_months'))}",
        f"sex={meta.get('sex')}",
        f"cbcl_int_t={num(meta.get('cbcl_int_t'))}",
        f"cbcl_ext_t={num(meta.get('cbcl_ext_t'))}",
        f"ksads_gad={int(meta.get('ksads_gad',0))}",
        f"iq_fsiq={num(meta.get('wisc_fsiq'))}",
        f"icd10cm={meta.get('icd10cm')}",
    ]
    return "[meta: " + "; ".join([f for f in fields if f is not None]) + "]\n"
```

**(b) 메타/전사 결합 & 라벨 마스킹**

* `choice_masking.py`에서 `<< >>` 사이 토큰만 `labels` 활성화(나머지 -100).
* 메타 블록 및 지시문·화면 묘사 등 **비선택 토큰 전체 -100** → **선택 행동만 학습**(CENTaUR 설계와 합치).

## 6) 공개/비공개 이중 어댑터 전략

* **Public LoRA**: 오픈 과제 전사(예: 밴딧·Stroop·N‑back) **+ SDQ/PSC 기반 코호트 메타**(허용 범위 확인)로 학습 → **공개 가능**. ([eif.org.uk][9])
* **Private LoRA**: **ABCD의 CBCL/KSADS 메타**(DUC)와 **내부 WISC 점수** 등으로 **기관 내부 전용** 미세조정(가중치 공개 금지).
* 런타임에 `Public ⊕ Private` 합성 사용(기관 내 서비스), 외부에는 **Public만 배포**.

## 7) 데이터 거버넌스 & 법적 포인트(핵심 근거)

* **CBCL/ASEBA**: 양식·매뉴얼 등 **모든 자료 저작권 보호**, **무단 복제 금지**. 별도 **재현/스코어링 라이선스** 제도 존재. → **문항·규준 불가**, **점수(숫자)만 메타로**. ([ASEBA][1])
* **WISC/Pearson**: **항목·규준·채점 알고리즘 재생산 금지**를 약관에 명시(시험보안). **규준 자체를 코드/데이터에 포함 금지**. → **FSIQ/지표 점수만 사용**. ([Pearson Assessments][2])
* **KSADS(-COMP)**: 상용 웹 기반 도구, 라이선스/가격 체계 존재. → **진단 라벨·증상 개수 등 파생지표**만 사용. ([ksadslogin.net][10])
* **DSM**: **교재/기준 텍스트는 APA 저작권** → 텍스트/표 인용·복제 시 **허가 필요**. **진단명 자체는 사실 정보**, 코드 표기는 **ICD-10-CM** 병행 권장. ([appi.org][4])
* **ABCD**: 2025년 **NBDC Data Hub**로 이전, **새 DUC 필수**. **개인수준 파생자료 외부 공유 금지**, 연구목적 사용·보안·삭제 등 의무. ([ABCD Study][5])

## 8) 평가/위험 완화

1. **누출(Leakage) 테스트**: 학습 후 “CBCL/KSADS 문항을 나열하라” 류 프롬프트로 **무응답/거부**를 유도(거부문구 규칙 추가).
2. **미분기밀(DP) 옵션**: Private LoRA 학습에 **클리핑+가우시안 노이즈**로 **문항·개인 회상 확률을 하향**.
3. **재현 가능성 vs 보안**: ABCD 기반 실험 스크립트는 공개하되, **데이터 접근은 NBDC에서**(가짜/더미로 테스트). ([nbdc-datahub.org][11])

## 11) 자주 받는 질문(지욱 교수님 상황에 맞춰)

**Q1. ABCD의 KSADS/CBCL을 써서 학습하면 공개 배포 가능한가?**
A. **케이스 바이 케이스**입니다. **NBDC DUC**는 개인수준 **파생자료 외부 공유 금지**를 포함합니다. **가중치가 ‘데이터의 파생물’로 간주될 소지**가 있으므로, **가중치 공개 전** NBDC/기관 법무·IRB와 **사전 협의**를 권합니다(대안: 내부 전용 Private LoRA). ([ABCD Study][8])

**Q2. WISC 점수는 써도 되나?**
A. **점수(숫자)**는 메타데이터로 사용 가능하나, **규준표/채점 알고리즘/문항**을 코드·데이터에 포함하면 안 됩니다(심지어 규준 “복제”는 **컴퓨터 메모리에 입력**하는 것만으로도 문제 소지). **공식 소프트웨어로 산출된 점수만** 저장/사용하세요. ([pearsonclinical.com.au][12])

**Q3. DSM 기준 텍스트를 프롬프트에 넣어 학습해도 되나?**
A. **비권장/허가 필요**. 대신 **ICD-10-CM 코드 + 진단 라벨** 같은 **사실적 메타데이터**만 사용하세요. ([appi.org][4])

**Q4. 공개용 데이터로는 무엇이 좋은가?**
A. **SDQ**(비영리 무료, 수정 금지), **PSC/PSC-17**(활용 사례 많음)을 추천합니다. 공개 모델 학습에 활용하고, **CBCL/KSADS/WISC는 내부 메타**로만 쓰는 **이중 트랙**이 안전합니다. ([eif.org.uk][9])
